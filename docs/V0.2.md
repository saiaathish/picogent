# Picogent v0.2 — Finish the Loop

Picogent v0.2 is the small, single-agent coding loop you can hand a complete
task. It keeps the existing one-folder, one-binary design while adding enough
state and evidence to finish work safely:

```text
prompt
  → infer a compact task
  → map the repository on demand
  → checkpoint touched files
  → edit and run targeted verification
  → run the broader affected checks
  → repair a failure (at most three times)
  → done, blocked, or waiting for permission
```

## Durable task state

Task state is separate from chat history and is stored at
`.picogent/tasks/<session-id>.json` inside the workspace. It contains only the
goal, status, steps, current step, attempts, changed files, verification
evidence, and a blocker when one exists. Informational prompts do not create a
task. `planning`, `working`, `verifying`, `blocked`, and `done` are the only
statuses; `done` is terminal for that session.

The state follows the session in both the GUI and TUI. New, loaded, reset, and
cleared sessions select a fresh task session, and stale canceled turns cannot
publish progress into a newly selected session.

## Verification and recovery

`verify` detects the repository's runner, runs a safe targeted command for
changed paths, then the broader suite. Each stage records `PASS`, `FAIL`,
`INCONCLUSIVE`, or `SKIPPED` evidence. A failed check can trigger a bounded
repair loop; the hard limit is three repair attempts. Missing runners and
unavailable tools remain inconclusive or blocked instead of being reported as
success.

The existing heuristics handle the common small failures without adding a
second agent: verification failures feed concise evidence back into the next
turn, writes are checkpointed before execution, and recovery conflicts preserve
the displaced file for inspection.

## Checkpoints and undo

Every modifying turn snapshots only the paths it touches. A sealed checkpoint
is offered as `Undo: /undo`; restore refuses newer user changes and reports
conflicts or recovery paths rather than overwriting them. A failed or canceled
turn cannot replace a previously usable undo checkpoint.

## Learned project playbooks

Successful verified turns may update the existing self-evolution store with a
small habit or playbook. Relevant playbooks are selected by prompt overlap and
injected into the next execution prompt within the existing 720-character
budget. Archived or irrelevant playbooks are not injected, so memory remains a
hint rather than a second repository index.

## Native progress UI

The GUI and TUI expose the same task state: status, goal, steps, attempts,
changed files, verification progress, completion proof, and a blocker when
work stops. Completion proof reports whether the recorded criteria and
verification evidence are sufficient, with a reason when proof is pending.
The GUI
reuses the existing Changes and Activity surfaces, keeps keyboard focus inside
the review tabs, and exposes semantic tab/tabpanel relationships. It is native
HTML/CSS/JavaScript with no new runtime dependency or background process.

## Release acceptance test

The release-defining loop is executable without credentials or a network model:

```bash
go test ./internal/acceptance -run TestV02ReleaseLoop -count=1
```

The test creates a real temporary Go repository with a crashing last-item
delete, proves the baseline failure, drives the normal agent tools through map →
read → write → verify, asserts targeted and broader passing evidence plus
durable `done` state, and then confirms `/undo` restores the failing pre-turn
source.

## Verification gates

Before a release checkpoint, run:

```bash
go test -race ./internal/agent ./internal/gui ./internal/tui ./internal/taskstate ./internal/acceptance
go test ./...
go vet ./...
go build ./cmd/picogent
```

CI repeats the full test/build/GUI-listen smoke on Ubuntu, macOS, and Windows.

Picogent still deliberately has no subagents, embeddings index, watcher,
background daemon, IDE clone, or hosted service. The v0.2 loop remains one small
Go harness with visible permissions and a real, reversible result.
